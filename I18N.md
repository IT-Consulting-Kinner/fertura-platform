# Internationalisierung (i18n) — Entwicklerleitfaden

Mehrsprachigkeit für Core, Module und Extensions. Basissprache ist **Englisch**;
fehlende Übersetzungen fallen flach auf Englisch zurück. Entscheidungen siehe
`IMPLEMENTATION_PLAN.md` (E37–E44).

## 1. Übersetzungen verwenden

CakePHP-I18n mit **symbolischen Schlüsseln** (`<bereich>.<sache>.<variante>`):

```php
__('auth.login.submit');                 // Core-Domain `default`
__d('ticketing', 'ticket.create.title'); // Modul-Domain = component_key
__('flash.user.created', $name);         // mit Platzhalter (%s, sprintf)
__x('count', 'tickets.badge', ...);      // Kontext-Variante
```

In Templates immer durch `h()` escapen: `<?= h(__('admin.config.title')) ?>`.

- **Schlüssel statt Klartext.** Keys sind stabil und versions-tauglich; der
  englische Text steht in der PO-Datei, nicht im Code.
- **Domain.** Core nutzt `default`. Jedes Modul/jede Extension nutzt seinen
  `component_key` als Domain (`__d('<key>', '<key>...')`).

## 2. Sprachdateien mitliefern

Jede Komponente bringt **mindestens Englisch** für ihre Version mit. Format:
GNU-`.po` (CakePHP liest PO zur Laufzeit direkt — **kein** MO-Kompilat nötig).

### Core
```
core/resources/locales/<locale>/default.po      # en_US ist kanonisch
```
Die mitgelieferten Core-Kataloge bleiben in `resources/locales` (immer die
aktuelle Core-Version). Sie werden **nicht** in den Store dupliziert (E43).

### Module / Extensions (im Paket)
```
<paket>/locales/<locale>/<domain>.po            # domain = component_key
```
Plus Manifest-Eintrag:
```json
"locales": { "domain": "ticketing", "supported": ["en_US", "de_DE"] }
```
Bei der **Installation** kopiert der Lifecycle die Paket-`locales/` in den
Managed Locale Store; die Signaturprüfung des Pakets bestimmt `signed`
(`source=package`).

Locale-Format: `ll_CC` (`en_US`, `de_DE`). Beispiel-PO:
```po
msgid ""
msgstr ""
"Language: de_DE\n"
"Content-Type: text/plain; charset=UTF-8\n"

msgid "ticket.create.title"
msgstr "Ticket anlegen"
```

> **Platzhalter-Vertrag — Modul-Domänen sind sprintf, NICHT ICU.** Modul-/Extension-
> Kataloge werden immer mit dem **sprintf**-Formatter geladen (`StoreLocaleLoader`
> pinnt jede Modul-Domäne auf `new Package('sprintf', …)`, und der Package-Formatter
> schlägt den globalen Default). Platzhalter deshalb als `%s`/`%d` schreiben —
> **niemals** ICU `{0}`/`{1}`. Ein ICU-Platzhalter in einer Modul-`.po` bleibt im
> Render roh stehen (das Argument geht verloren). `bin/cake module_lint` warnt bei
> ICU `{n}` in `locales/*.po` (Autoren-/CI-Zeit).

## 3. Managed Locale Store

Persistentes Volume `<ROOT>/language-store`, DB-Tabelle `core.language_packs`
hält nur **Metadaten**.

```
<store>/<component_key>/<version>/<locale>/<domain>.po
```

- **Sicheres Schreiben** (`LanguagePackStore`): `.tmp` + `fsync` → atomarer
  Rename (kein Lösch-Fenster). PostgreSQL-Advisory-Lock je Datei serialisiert
  und unterscheidet *in-flight* (Lock gehalten) von *verwaist* (Lock frei).
- **Selbstheilung:** `bin/cake lang recover` promotet vollständige `.tmp`
  (Original fehlt) und bereinigt verwaiste. `bin/cake lang path` zeigt den Pfad.
- **Status-Trio** je Pack: `signed` (Herkunft beim Import), `reviewed`,
  `edited`. Signatur wird **nur beim Import** geprüft; Editieren invalidiert sie
  nicht, setzt aber `edited=yes` und `reviewed=yes` (Admin-Edit = Review).

## 4. Versions-Gate & Auflösung (`LocaleResolver`)

Je (Komponente, Locale) wird gegen die **aktive Komponentenversion** aufgelöst:

| Pack-Version vs. aktiv         | Verhalten            | Status   |
|--------------------------------|----------------------|----------|
| identisch                      | genutzt              | `clean`  |
| gleiche Major, andere Minor/…  | genutzt (höchste)    | `notice` |
| andere Major / keine           | nicht genutzt → EN   | `error`  |

- **Wählbare Sprachen** = `locale.enabled` ∩ Sprachen, für die der **Core** eine
  nutzbare Datei hat (`LocaleResolver::selectableLocales`). Englisch immer.
- Der Status wird **berechnet**, nicht gespeichert (Verwaltung + Health).

## 5. Anzeigesprache zur Laufzeit

`LocaleMiddleware` (nach der Authentication-Middleware). Präzedenz, jeweils nur
für **aktivierte** Locales:

1. `?lang=…` → Session-Override
2. Session-Override
3. Benutzer-Präferenz `user.locale`
4. `Accept-Language` (q-Gewicht, Sprach-Präfix)
5. System-Default `locale.default`

Umschalten: View-Cell `LocaleSwitcher` (Admin = persistent via
`POST /locale/change` → `user.locale`; Login/öffentlich = Session via `?lang`).

Einstellungen (Core-Konfiguration): `locale.default` (Default `en_US`),
`locale.enabled` (JSON-Liste, Default `["en_US","de_DE"]`).

## 6. Sprachverwaltung (Admin-Bereich „Sprachverwaltung")

`/admin/localization` (fester 7. Bereich, Recht `localization`):

- **Übersicht:** aktive/inaktive Komponenten, Packs gruppiert mit Status
  (`clean/notice/error`) und Flags (`signed/reviewed/edited`).
- **Feld-Editor:** bearbeitet nur die Übersetzung (`msgstr`); `msgctxt`,
  Plurale, Kommentare und Schlüssel bleiben erhalten (`PoDocument`, verlustfrei).
  Speichern schreibt atomar (Store) und setzt `edited=yes`/`reviewed=yes`.
- **Import:** unsignierter `.po`-Upload (E42) mit Review-Vorschau, Re-Import-
  Warnung bei `edited`; `source=upload`, `signed=no`, `reviewed=no`. Signierte
  Packs kommen ausschließlich über die Paketinstallation.
- **Löschen:** aktive Komponente — alles außer Englisch; inaktive — alles
  (inkl. Englisch). Deinstallation behält Sprachdateien.
- **Review:** setzt `reviewed=yes`.

Alle Aktionen (`lang.import/edit/delete/review`) werden ins **Audit-Log**
geschrieben (`entity_type=language_pack`).

## 7. Health

Subsystem `localization` in `HealthService::report()` meldet `degraded` bei:
fehlender Englisch-Basis aktiver Komponenten, Versionsfehlern (Major-Mismatch
genutzter Packs) oder verwaisten/in-flight `.tmp` im Store. Read-only —
Heilung über `bin/cake lang recover`.

## 8. Checkliste für neue Komponenten

- [ ] Alle UI-/Flash-/Mail-Texte über `__()`/`__d()` mit symbolischen Schlüsseln.
- [ ] Platzhalter als sprintf `%s`/`%d`, **nie** ICU `{0}`/`{1}` (Modul-Domänen sind
      sprintf-gepinnt; `module_lint` warnt bei ICU `{n}`).
- [ ] `locales/<locale>/<domain>.po` für **mindestens** `en_US` mitliefern.
- [ ] Manifest-`locales` mit `domain` (= `component_key`) und `supported`.
- [ ] Schlüssel stabil halten; bei Breaking-Key-Änderungen Major erhöhen
      (Versions-Gate setzt alte Packs auf `error`).
